# T007 — Aggregate checks and CI

## Goal and references
Finish Phase 0 tooling by making local and CI gates consistent. Read root `Makefile`, backend/frontend manifests, `compose.yaml`, and `docs/rules-checklist.md`.

## Allowed files
Update `Makefile`; create `.github/workflows/ci.yml`. Codex will generate a backend constraints file from the actual tested environment separately.

## Constraints
Read/edit tools only; no shell commands, installs, Git operations, business behavior, models, generators, migrations, schema/API changes or deployment. CI checks are local repository tooling, not a website publishing workflow. Use Python 3.13 and Node 20 to match the tested environment. Install backend using declared pyproject dev dependencies and frontend with npm ci. Honor `backend/requirements-dev.lock` as pip constraints if Codex has supplied it. No API keys or external data. Docker compose config can be checked without a daemon using `.env.example`. Do not run integration containers in CI until their smoke path is verified. Never report checks as run.

## Acceptance and exact checks (Codex runs)
`make test` aggregates the backend and frontend suites plus structure validation. `make lint` aggregates backend/script Ruff and frontend ESLint. Existing individual commands remain available. CI runs the equivalent test, lint and frontend build commands and validates Compose config. CI uses read-only contents permission. YAML is valid. These are the exact checks:
```
make test lint build-console
docker compose --env-file .env.example config --quiet
git diff --check
```
Report changed files and pending verification.
