## Requirements:

1. `backend/app/mandates/models.py`:
   - Pydantic v2 models conforming to `docs/api-contracts.md`:
     - `ErrorDetail(code: str, message: str)`, `ErrorResponse(error: ErrorDetail)`
     - `MandateRequest(user_id: str, agent_id: str, amount: float, purpose: str = 'cash_out')`
     - `MandateRequestResponse(mandate_id: str, status: str = 'requested', next: str = 'verify', verification_modes: list[str])`
     - `MandateVerifyRequest(mode: str, stated_amount: float, attempt: int = 1)`
     - `MandateVerifyResponse(outcome: str, decision: str, status: str, expires_at: str, code_delivery: str, one_time_code: str | None = None, case_id: int | None = None)`
     - `MandateRedeemRequest(code: str)`
     - `MandateRedeemResponse(txn_id: int | None = None, amount: float, fee: float = 0.0, status: str = 'redeemed')`
     - `MandateConfirmCashRequest(cash_received: float)`
     - `MandateConfirmCashResponse(gap: float, flagged: bool, case_id: int | None = None)`
     - `MandateRevokeResponse(mandate_id: str, status: str = 'revoked')`

2. `backend/app/mandates/service.py`:
   - `MandateService` class implementing in-memory state with PostgreSQL integration:
     - Policy rules loaded from `data/config.yaml`:
       - `user_cap_default`: 5000.0 BDT default mandate cap.
       - `daily_cash_out_limit`: 25000.0 BDT daily limit.
       - `mandate_ttl_minutes`: 15 minutes.
       - `max_verification_attempts`: 2 attempts.
       - `cash_gap`: min_bdt = 50.0, rate = 0.02.
     - `request_mandate(user_id, agent_id, amount, purpose="cash_out")`:
       - Validates amount > 0 and amount <= user_cap_default (reject with 422 if exceeded).
       - Checks user daily total + amount <= daily_cash_out_limit (reject with 422 if exceeded).
       - Rejects if user has existing active/requested unexpired mandate with 409 `ACTIVE_MANDATE_EXISTS`.
       - Generates UUID mandate_id, status = 'requested', logs to audit_log.
     - `verify_mandate(mandate_id, mode, stated_amount, attempt=1)`:
       - Checks attempt <= max_verification_attempts.
       - If stated_amount == mandate.amount: outcome = 'match', decision = 'ISSUE_MANDATE', status = 'active'.
       - Generates cryptographically secure 6-digit one-time code (`secrets`), hashes with SHA-256 (`code_hash`). Plain code is NEVER stored in database.
       - Sets `expires_at = now + mandate_ttl_minutes` (15 mins).
       - If stated_amount != mandate.amount: outcome = 'mismatch', decision = 'REVIEW', status = 'rejected' or creates case in cases table.
       - Logs to audit_log.
     - `redeem_mandate(mandate_id, code)`:
       - Rejects if status == 'redeemed' with 409 `ALREADY_REDEEMED`.
       - Rejects if status == 'locked' with 423 `ACCOUNT_LOCKED`.
       - Rejects if now > expires_at with 410 `MANDATE_EXPIRED`.
       - Verifies SHA-256 of code against stored code_hash.
       - On wrong code: increments failure counter; if failures >= 3, sets status = 'locked' and returns 423 `ACCOUNT_LOCKED`; otherwise returns 401 `INVALID_ONE_TIME_CODE`.
       - On valid code: sets status = 'redeemed', assigns synthetic txn_id, logs to audit_log, returns 200.
     - `confirm_cash(mandate_id, cash_received)`:
       - Computes gap = abs(amount - cash_received).
       - Tolerance = max(min_bdt, rate * amount).
       - If gap > tolerance: flagged = True, records review case.
       - Logs to audit_log.
     - `revoke_mandate(mandate_id, actor)`:
       - Sets status = 'revoked', logs to audit_log.

3. `backend/app/mandates/router.py`:
   - FastAPI `APIRouter(prefix="/api/v1/mandates", tags=["mandates"])` exposing:
     - `POST /request`
     - `POST /{id}/verify`
     - `POST /{id}/redeem`
     - `POST /{id}/confirm-cash`
     - `POST /{id}/revoke`
   - Maps domain exceptions cleanly to HTTP 400, 401, 404, 409, 410, 422, 423.

4. `backend/app/mandates/__init__.py`:
   - Exports `MandateService`, `router`, and models.

5. `backend/tests/test_mandates.py`:
   - Comprehensive unit and integration test suite:
     - Happy path lifecycle: request -> verify -> redeem -> confirm-cash.
     - 422 on amount exceeding 5000 BDT cap.
     - 422 on daily cash-out limit exceeding 25000 BDT.
     - 409 on second concurrent active mandate for same user.
     - 410 on redeeming expired mandate.
     - 401 on wrong one-time code.
     - 423 on 3 consecutive wrong code attempts (lockout).
     - 409 on attempting to redeem already-redeemed mandate.
     - Verification that plain code is never stored in mandate records (only SHA-256 hash).
     - Cash gap below tolerance (e.g. 20 BDT) unflagged; cash gap above tolerance (e.g. 200 BDT) flagged with case opened.
     - Revocation lifecycle.
     - Audit log verification.
