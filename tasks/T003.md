# T003 — Empty component structure and dependency manifests

## Goal and references
Prepare empty component boundaries for the Phase 0 skeleton. Read `docs/architecture.md` and the Phase 0 row in `tasks/BOARD.md`.

## Allowed files
Create `backend/pyproject.toml`, empty Python package markers under `backend/app/` and its `features`, `models`, `policy`, `mandates`, `verification`, `copilot` packages, and `backend/tests/.gitkeep`. Create `frontend/package.json` and `frontend/src/.gitkeep`. Add `scripts/check_structure.py` and a root `Makefile` with only a `check-structure` target for now.

## Constraints
No application behavior, data generation, models, schema changes, policy implementation, configuration changes, package installation, commits, push, remote or deployment. Synthetic data only; no secrets. Do not touch docs or unrelated files. Use Python >=3.11 and Node >=20. Record only dependencies needed for the skeleton: FastAPI and uvicorn, development pytest/httpx/ruff; React/ReactDOM and development Vite/Vitest/ESLint with compatible major ranges. ML dependencies come with their later tasks. Use setuptools for backend package discovery under app; include a test/lint config in pyproject. Do not claim checks ran unless you ran them.

## Acceptance and exact test command
The directory boundaries exist as empty packages. Both manifests parse. The structure checker checks required paths and parses manifests using Python stdlib (`tomllib`, `json`), without needing installed application packages. `make check-structure` passes. This is a tooling check, not a domain feature test.

Run `make check-structure` if command permission is granted; otherwise report it as pending Codex verification. Report all changed files. Do not commit or push.
