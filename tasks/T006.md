# T006 — Docker Compose skeleton

## Goal and references
Make the generic Phase 0 stack runnable with PostgreSQL, API and frontend. Read `docs/architecture.md`, `.env.example`, backend and frontend manifests, and root `Makefile`. Do not apply `docs/schema.sql` yet.

## Allowed files
Create `compose.yaml`, `backend/Dockerfile`, `backend/.dockerignore`, `frontend/Dockerfile`, `frontend/.dockerignore`, `scripts/smoke_skeleton.py`; update `.env.example` and `Makefile` for `smoke-skeleton`.

## Constraints
No business logic, migrations, generator/seed commands, model/policy/verification code, production claims, deployments or remote changes. No real credentials in Git. Use read/edit tools only; Codex runs shell, build, test and smoke commands. Use Python 3.13, Node 20 build image, PostgreSQL 16, and a static frontend serving container. Backend listens on 0.0.0.0 inside the container; published ports bind localhost only. Persist Postgres in a named dev volume. Require POSTGRES_PASSWORD through an env var, with CHANGE_ME in `.env.example`; don't put a password literal in compose. Configure a Postgres readiness check and API dependency. The skeleton API does not use the DB yet. Follow the existing dependency manifests; use npm lockfile in the frontend image. Apply backend/requirements-dev.lock as constraints when installing the backend runtime (do not install dev extras in its image). Do not add unused runtime dependencies. Smoke checker uses Python stdlib HTTP requests to check API health and the generic frontend page, with bounded retries and configurable local URLs. Keep existing make targets.

## Acceptance and checks (Codex runs)
```
docker compose --env-file .env.example config --quiet
docker compose --env-file .env.example up --build -d
make smoke-skeleton
make check-structure test-api lint-api test-console lint-console build-console
git diff --check
```
The full stack is generic scaffolding; no domain data is generated. Report changed files and checks pending Codex verification.
