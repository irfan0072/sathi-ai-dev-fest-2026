## Dashboard path when the human chooses deployment

1. Make the submission repository public in GitHub. Its current authenticated private access works for development; judges need anonymous access.
2. In Render, choose New → Blueprint and connect `irfan0072/sathi-ai-dev-fest-2026`, branch `main`, root `render.yaml`. Review the proposed `sathi-db`, `sathi-api` and `sathi-console` resources and plans before applying.
3. Initial Blueprint prompts may appear before public URLs exist. If needed, enter `https://setup.invalid` for the two URL fields to keep initial browser access disabled; this is a setup placeholder, never a live URL. Once resources exist, replace both fields in their Environment tabs. Set `VITE_API_URL` to the API's actual public HTTPS URL. Obtain it from the dashboard; do not use the private-network hostname or guess the service suffix. Set `CORS_ORIGINS` to the console's exact public HTTPS origin. Browser API requests require these to agree. After changing `VITE_API_URL`, rebuild the static console because Vite embeds it at build time.
4. Keep `DATABASE_URL` linked to managed Postgres, `JWT_SECRET` generated by Render, `SATHI_CONFIG=data/config.yaml`, and the pinned Python runtime from the verified blueprint. Never paste server secrets into chat or commit them. Public synthetic fixture PINs below are intentionally separate from the signing secret.
5. The startup command `PYTHONPATH=backend python -m app.bootstrap` applies existing migrations and seed only the small namespace777 demo fixture. Repeated startup must preserve spent balances and cases. It verifies the committed small artifact bundle; no full simulation generation, model fitting or train/test seeding on startup. Free web services have no dashboard shell, so no manual shell step is required.
6. Provide the actual API and console URLs for independent health, authentication, artifact and full-flow verification. Deployment is complete only after that remote smoke passes; a successful build alone is insufficient.

The blueprint defines a managed database, API web service and static console. [Render Blueprint reference](https://render.com/docs/blueprint-spec). The static resource omits unsupported plan/region fields, the API uses generated signing credentials, and Postgres16 has external access blocked with `ipAllowList: []`. URL fields use `sync: false`: dashboard prompts occur only on initial creation; subsequent edits are manual. No private API hostname is used as a browser URL.
