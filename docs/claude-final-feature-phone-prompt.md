## Architecture: ordinary cellular voice, optional ASR, deterministic keypad fallback

A feature phone must be able to participate through an ordinary cellular call without an app, browser, account login or handset mobile data. Cellular voice coverage is still required. The provider and backend need their own connectivity. Receiving a browser-simulated call is a local demonstration, not proof of an actual feature-phone connection.

Reuse the existing provider adapters, persisted call/check state, retry budgets, independent-follow-up queue and deterministic amount interpreter. Inspect `backend/app/voice/twiml.py`, `voice/service.py`, `voice/router.py`, `callcenter/interpret.py` and the existing Bangladesh HTTP IVR adapter. Do not replace them with a parallel transaction system or pretend the generic adapter is an established contract with Robi, Grameenphone or Banglalink.

The intended production path is:

Cash-out event → existing confirmation queue → provisioned voice/IVR provider → ordinary cellular call → short Bangla prompt → spoken amount OR keypad input → deterministic validation → neutral acknowledgement → appropriate staff case/follow-up.

1. **Make keypad-only operation a first-class working mode.** Offer simple Bangla prompts, a repeat/help path, and an explicit keypad mode. After low-confidence/unusable speech, ASR failure or speech-provider timeout, the next collection step must be DTMF-only, with state persisted across callbacks and retries. Current `_check_digits` uses `speech=True` again, so the purported fallback still listens to speech. Twilio mixed `dtmf speech` gives precedence to the first detected input; background speech can preempt keypad input. Tests must assert the emitted provider response actually switches to `input="dtmf"`, not merely changes its wording. Keep a bounded retry budget, then neutral human-follow-up/unreachable handling. Missing confidence is not an invented confident result.

2. **Correct empty-input versus denial handling before adding channels.** `voice/router.py` currently relies on a `FinishedOnKey` callback field, but that field is absent from the documented Twilio Gather contract. `callcenter/interpret.py` can interpret an empty response as denial. Reproduce with a valid signed empty Gather callback that has neither Digits nor SpeechResult nor FinishedOnKey. Silence/timeouts/ambiguous empty input must never become denial, confirmation or fraud evidence. Introduce an explicit, unambiguous denial menu command/state that does not collide with amount entry, language/help keys or the existing leading-zero duress convention. Update prompts, adapters, simulator and tests consistently. A bare termination key is not proof of denial unless an actual provider contract supplies reliable termination metadata; otherwise reprompt. Retain meaningful explicit denial behavior and preserve duress safety.

3. **Keep financial interpretation deterministic.** The system should compare what the customer actually entered/spoke with the recorded transaction; do not leak the expected answer into ASR hints or invent recognized amounts. Never collect PIN/OTP. Do not let an LLM approve transfers, block accounts, classify guilt, clear cases or infer duress from emotion. Full STT → LLM → TTS can later run on the backend over a verified streaming voice transport, but is optional, not required for basic feature-phone support. This deadline does not authorize building an unverified streaming stack or claiming fine-tuned Bangla ASR. Fixed Bangla audio/TTS and reliable keypad input are the required core. Describe any future conversational assistant as bounded and separate from authorization.

4. **Normalize provider events at the existing adapter boundary.** Reuse existing correlation/signature/idempotency controls and close gaps only where needed. Bind call/check context server-side; validate provider origin and call identifiers. Handle speech, digits, no-input, disconnect and provider errors distinctly. Repeated or late callbacks must not create duplicate cases, retry forever, overwrite terminal results or expose secrets. Persist the input mode and attempts so restarting the process does not reset safety limits. Document vendor-specific assumptions and unresolved contract requirements rather than inventing payload fields.

5. **No mobile data is different from no cellular coverage.** With no voice coverage, leave the check pending/unreachable and use bounded later retries or staff follow-up; do not show successful offline confirmation. Respect existing contact policy, timing and opt-out behavior. Do not guarantee free calls, trusted caller identification, network availability or toll-free service without a provider contract. The customer should receive a neutral explanation and anti-phishing guidance appropriate to this service.

## USSD: separate optional service, not automatic in-call fallback

DTMF keypad input travels inside the same call. USSD needs a separately provisioned operator/aggregator service and assigned code. Do not claim the voice call can automatically turn into a USSD session. Do not invent an upay shortcode, operator partnership, public phone number or live callback connection. Real USSD activation is a rollout dependency.

If time remains after essential safety fixes, add a small, explicitly labeled **local USSD simulation** plus a documented adapter contract that reuses the same post-cash-out confirmation service:

- A short menu identifies an eligible pending confirmation, accepts the received amount, permits repeat/help or explicit denial, and ends with neutral wording. Limit menu depth and session duration. Do not perform a new cash-out, debit or financial authorization.
- Persist session state/expiry on the server; bind the session to an authenticated provider-reported phone and eligible check. Do not trust a client-supplied phone, raw check ID, accumulated menu text or claimed step as production identity/state. Define safe handling for multiple pending checks. Simulator identity comes only from an authorized synthetic fixture and must not masquerade as authenticated telco identity.
- Apply authenticated gateway callbacks, expiry, replay/duplicate protection, rate limits, correlation and an audit record. State the chosen provisional protocol explicitly; `CON`/`END` conventions are not proof of a Bangladesh provider contract. Avoid introducing an unauthenticated new public write endpoint.
- Cancellation, expiry, network loss and malformed input must not confirm a transaction. Input from the same agent-controlled phone does not satisfy independent contact; preserve the server clearance gate and urgent follow-up.
- Reuse the existing synthetic customer/demo screen for a button-phone panel with clearly marked Call, Keypad and optional USSD simulation. Label “handset mobile data not required in intended cellular deployment” rather than pretending a web toggle disables the network. Do not add an actual smartphone requirement to the production journey.
